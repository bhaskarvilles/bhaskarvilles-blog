================================================================================
1. HOW IT WORKS
================================================================================

A. PRIMARY DOMAIN (bhaskar.blog)
---------------------------------
- This is your main domain set in hugo.toml (baseURL)
- All canonical URLs point to this domain
- Search engines will index this domain
- All structured data uses this domain

B. ALTERNATE DOMAIN (bhaskarvilles.blog)
-----------------------------------------
- Configured in hugo.toml under params.alternateDomains
- Automatically redirects to primary domain (301 redirect)
- Preserves the full URL path during redirect
- Example: bhaskarvilles.blog/post/ai-trends/ → bhaskar.blog/post/ai-trends/

C. SEO BENEFITS
---------------
✓ No duplicate content issues
✓ Link equity consolidated to primary domain
✓ Clear canonical URLs for search engines
✓ Proper alternate domain signals
✓ 301 redirects preserve SEO value

D. FOR APACHE SERVER
--------------------
1. Configure virtual hosts for both domains:

<VirtualHost *:80>
    ServerName bhaskar.blog
    ServerAlias bhaskarvilles.blog
    DocumentRoot /var/www/html
    
    # Redirect HTTP to HTTPS
    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule ^(.*)$ https://%{HTTP_HOST}$1 [R=301,L]
</VirtualHost>

<VirtualHost *:443>
    ServerName bhaskar.blog
    ServerAlias bhaskarvilles.blog
    DocumentRoot /var/www/html
    
    # SSL Configuration
    SSLEngine on
    SSLCertificateFile /path/to/cert.pem
    SSLCertificateKeyFile /path/to/key.pem
    
    # .htaccess will handle redirects
    AllowOverride All
</VirtualHost>

2. The .htaccess file will handle redirects automatically

E. FOR NGINX SERVER
-------------------
1. Create nginx configuration:

# Redirect bhaskarvilles.blog to bhaskar.blog
server {
    listen 80;
    listen 443 ssl http2;
    server_name bhaskarvilles.blog www.bhaskarvilles.blog;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
    
    return 301 https://bhaskar.blog$request_uri;
}

# Redirect www.bhaskar.blog to bhaskar.blog
server {
    listen 80;
    listen 443 ssl http2;
    server_name www.bhaskar.blog;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
    
    return 301 https://bhaskar.blog$request_uri;
}

# Main server block
server {
    listen 80;
    listen 443 ssl http2;
    server_name bhaskar.blog;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
    
    root /var/www/html;
    index index.html;
    
    # Force HTTPS
    if ($scheme = http) {
        return 301 https://$server_name$request_uri;
    }
    
    # Add alternate domain header
    add_header Link '<https://bhaskarvilles.blog>; rel="alternate"';
    
    # Security headers
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header X-XSS-Protection "1; mode=block";
    add_header Referrer-Policy "strict-origin-when-cross-origin";
    
    location / {
        try_files $uri $uri/ =404;
    }
}

2. Test configuration: sudo nginx -t
3. Reload nginx: sudo systemctl reload nginx

A. AUTOMATIC SSL (Recommended)
-------------------------------
Most hosting platforms provide free SSL:

Netlify:     Automatic via Let's Encrypt
Vercel:      Automatic via Let's Encrypt
Cloudflare:  Automatic via Cloudflare SSL

B. MANUAL SSL (Self-Hosted)
----------------------------
Use Let's Encrypt with Certbot:

1. Install Certbot:
   sudo apt-get install certbot python3-certbot-apache
   # OR for nginx:
   sudo apt-get install certbot python3-certbot-nginx

2. Get certificates for both domains:
   sudo certbot --apache -d bhaskar.blog -d www.bhaskar.blog -d bhaskarvilles.blog -d www.bhaskarvilles.blog
   
   # OR for nginx:
   sudo certbot --nginx -d bhaskar.blog -d www.bhaskar.blog -d bhaskarvilles.blog -d www.bhaskarvilles.blog

3. Auto-renewal is configured automatically

------------------
Issue: Redirects not working
Solution: 
- Check DNS propagation
- Clear browser cache
- Verify hosting configuration
- Check redirect file syntax

Issue: SSL certificate errors
Solution:
- Renew certificates
- Check certificate includes both domains
- Verify DNS points to correct server

Issue: Duplicate content in search results
Solution:
- Verify canonical URLs are correct
- Check 301 redirects are working
- Wait for Google to re-crawl (can take weeks)
- Use URL removal tool in Search Console
